Add one streaming replica

Creates a PostgreSQL 15 physical standby with a dedicated replication user and slot, then verifies streaming from both servers.

A replica is not a backup Deletes, bad writes, and some corruption can replicate immediately. Maintain independent, tested backups and WAL archiving according to the required recovery point.

Preconditions

  • Primary and standby run the same PostgreSQL major version: 15.
  • The target is confirmed as the new standby, not the primary.
  • The standby data volume has enough capacity and correct ownership.
  • The standby can reach primary TCP 5432; security rules restrict access to required hosts.
  • The standby's previous data directory, if any, will be preserved instead of deleted.

Verify both nodes are PostgreSQL 15

Run on the primary, then on the standby.

hostname -f
/usr/lib/postgresql/15/bin/psql --version
sudo -iu postgres psql -d postgres -c "SELECT version(), pg_is_in_recovery();"

Primary should show recovery f. A running old standby may show recovery t, but it must still be PostgreSQL 15.

Verify you are on the intended standby

hostname -f
ip -brief address
sudo pg_ctlcluster 15 main status

Tick this only after the hostname and private IP match the standby machine from the incident or change ticket.

Verify standby disk capacity and ownership

df -h "{{RUNBOOK_DATA_DIR}}" /var/lib/postgresql
sudo ls -ld "{{RUNBOOK_DATA_DIR}}" /var/lib/postgresql

The volume must fit the primary database plus WAL growth. Existing data directory ownership should be understood before it is moved.

Verify network access from standby to primary

nc -vz -w 5 "{{RUNBOOK_PRIMARY_IP}}" 5432

A timeout means routing, firewall, security group, or PostgreSQL listen configuration is not ready. Do not start pg_basebackup until this passes.

Verify the old standby directory will be preserved

RUNBOOK_OLD_DATA="{{RUNBOOK_DATA_DIR}}.before-replica-$(date -u +%Y%m%dT%H%M%SZ)"
printf 'Current data dir: %s\nPreserved as: %s\n' "{{RUNBOOK_DATA_DIR}}" "$RUNBOOK_OLD_DATA"

Tick this only when the preserved path is specific and approved. The runbook moves the directory; it does not delete it.

1. Fill replica inputs

Run the copied commands on the server named in each step. Fill the topology once here so the IPs, user, slot, data path, and password-file line are generated consistently.

The replication password is only used to render the command text on this page. Do not save this HTML page with a real password typed into it.

printf 'Primary: %s\nStandby: %s\nReplication user: %s\nSlot: %s\nData: %s\npgpass: %s\n' \
  "{{RUNBOOK_PRIMARY_IP}}" \
  "{{RUNBOOK_STANDBY_IP}}" \
  "{{RUNBOOK_REPL_USER}}" \
  "{{RUNBOOK_SLOT}}" \
  "{{RUNBOOK_DATA_DIR}}" \
  "{{RUNBOOK_PGPASS}}"
Stop conditionDo not continue while any value still says STANDBY_PRIVATE_IP or REPLACE_WITH_REPLICATION_PASSWORD.

2. Confirm the primary

Run on the primary. Recovery must be f.

hostname -f
sudo -iu postgres psql -d postgres -c "SELECT version(), pg_is_in_recovery();"
sudo -iu postgres psql -d postgres -c "SHOW config_file; SHOW hba_file; SHOW data_directory;"
sudo -iu postgres psql -d postgres -c "SHOW wal_level; SHOW max_wal_senders; SHOW max_replication_slots; SHOW listen_addresses;"

Required values are wal_level = replica, available WAL senders, available replication slots, and a listening address reachable from the standby. Changes to these server settings require a planned PostgreSQL restart.

If the primary is not configured, apply reviewed values during a maintenance window:

sudo -iu postgres psql -d postgres -c "ALTER SYSTEM SET wal_level = 'replica';"
sudo -iu postgres psql -d postgres -c "ALTER SYSTEM SET max_wal_senders = '10';"
sudo -iu postgres psql -d postgres -c "ALTER SYSTEM SET max_replication_slots = '10';"
sudo -iu postgres psql -d postgres -c "ALTER SYSTEM SET listen_addresses = '*';"
sudo pg_ctlcluster 15 main restart
sudo pg_ctlcluster 15 main status

Re-run the checks after restart. Choose capacity values based on all replicas, backups, and operational connections rather than copying 10 blindly into a larger topology.

3. Create or reset the replication user

Run on the primary. First inspect the role:

sudo -iu postgres psql -d postgres -c "\du {{RUNBOOK_REPL_USER}}"

If it does not exist, create it without putting a password in shell history:

sudo -iu postgres psql -d postgres
CREATE ROLE {{RUNBOOK_REPL_USER}} WITH LOGIN REPLICATION;
\password {{RUNBOOK_REPL_USER}}
\q

If it already exists, run \password for the same replication role in psql to reset it, then update the standby password file.

4. Authorize only this standby

On the primary, first ask PostgreSQL where its active pg_hba.conf file is. Do not guess the path.

RUNBOOK_HBA_FILE="$(sudo -iu postgres psql -d postgres -Atqc "SHOW hba_file;")"
RUNBOOK_HBA_BACKUP="${RUNBOOK_HBA_FILE}.before-replica-$(date -u +%Y%m%dT%H%M%SZ)"
printf 'Active pg_hba.conf: %s\n' "$RUNBOOK_HBA_FILE"
sudo test -f "$RUNBOOK_HBA_FILE"
sudo cp "$RUNBOOK_HBA_FILE" "$RUNBOOK_HBA_BACKUP"
sudo ls -l "$RUNBOOK_HBA_FILE" "$RUNBOOK_HBA_BACKUP"

Edit only the printed active file, then add this line:

sudo nano "$RUNBOOK_HBA_FILE"
host  replication  {{RUNBOOK_REPL_USER}}  {{RUNBOOK_STANDBY_IP}}/32  scram-sha-256

pg_hba.conf accepts IP addresses and CIDRs, not AWS security-group IDs. Configure security-group-to-security-group access separately in AWS.

sudo -iu postgres psql -d postgres -c "SELECT pg_reload_conf();"
sudo -iu postgres psql -d postgres -c "SELECT line_number, type, database, user_name, address, auth_method, error FROM pg_hba_file_rules WHERE '{{RUNBOOK_REPL_USER}}' = ANY(user_name);"

The rule must appear from the same active file and the error column must be empty.

5. Configure the standby password

Run on the standby as an administrator. Confirm the postgres home directory and use the configured password file path.

getent passwd postgres
sudo -iu postgres sh -c 'printf "postgres home: %s\n" "$HOME"'
sudo touch "{{RUNBOOK_PGPASS}}"
sudo chown postgres:postgres "{{RUNBOOK_PGPASS}}"
sudo chmod 600 "{{RUNBOOK_PGPASS}}"
sudo -iu postgres nano "{{RUNBOOK_PGPASS}}"

Add exactly one matching line:

{{RUNBOOK_PRIMARY_IP}}:5432:*:{{RUNBOOK_REPL_USER}}:{{RUNBOOK_REPL_PASSWORD}}
sudo chown postgres:postgres "{{RUNBOOK_PGPASS}}"
sudo chmod 600 "{{RUNBOOK_PGPASS}}"
sudo stat -c '%U:%G %a %n' "{{RUNBOOK_PGPASS}}"

Expected owner and mode: postgres:postgres 600.

6. Test authentication from the standby

sudo -iu postgres psql \
  "host=$RUNBOOK_PRIMARY_IP port=5432 user=$RUNBOOK_REPL_USER dbname=postgres replication=database" \
  -c "IDENTIFY_SYSTEM;"

Do not touch the standby data directory until this succeeds. A timeout is network access; password failure is credentials; a pg_hba.conf rejection is primary authorization.

7. Preserve the standby's current cluster

Run only on the confirmed standbyThese commands stop PostgreSQL and move its current data directory. Confirm hostname -f again before continuing.
hostname -f
sudo pg_ctlcluster 15 main stop
sudo pg_ctlcluster 15 main status
RUNBOOK_OLD_DATA="${RUNBOOK_DATA_DIR}.before-replica-$(date -u +%Y%m%dT%H%M%SZ)"
sudo mv "$RUNBOOK_DATA_DIR" "$RUNBOOK_OLD_DATA"
sudo install -d -o postgres -g postgres -m 700 "$RUNBOOK_DATA_DIR"
sudo ls -ld "$RUNBOOK_DATA_DIR" "$RUNBOOK_OLD_DATA"

Do not delete the preserved directory until the new replica is validated and the retention decision is approved.

8. Take the base backup

sudo -iu postgres /usr/lib/postgresql/15/bin/pg_basebackup \
  --host="$RUNBOOK_PRIMARY_IP" \
  --username="$RUNBOOK_REPL_USER" \
  --pgdata="$RUNBOOK_DATA_DIR" \
  --wal-method=stream \
  --write-recovery-conf \
  --checkpoint=fast \
  --create-slot \
  --slot="$RUNBOOK_SLOT" \
  --progress \
  --verbose

Wait for the command to return. Continue only when the exit code is 0:

PG_BASEBACKUP_EXIT=$?
printf 'pg_basebackup exit code: %s\n' "$PG_BASEBACKUP_EXIT"
test "$PG_BASEBACKUP_EXIT" -eq 0
sudo cat "$RUNBOOK_DATA_DIR/PG_VERSION"
sudo test -f "$RUNBOOK_DATA_DIR/standby.signal" && echo "standby.signal present"

If a retry says the slot already exists

The first attempt may have created the slot before failing. Check it on the primary:

sudo -iu postgres psql -d postgres -c "SELECT slot_name, active, restart_lsn, wal_status FROM pg_replication_slots WHERE slot_name = '{{RUNBOOK_SLOT}}';"

If it is the intended inactive slot, recreate an empty standby target as in step 7 and rerun pg_basebackup without --create-slot, keeping --slot="$RUNBOOK_SLOT". Do not drop an unfamiliar or active slot.

9. Start and verify the exact cluster

sudo pg_ctlcluster 15 main start
sudo pg_ctlcluster 15 main status
sudo -iu postgres psql -d postgres -c "SELECT pg_is_in_recovery(), pg_last_wal_receive_lsn(), pg_last_wal_replay_lsn(), now() - pg_last_xact_replay_timestamp() AS replay_delay;"
sudo -iu postgres psql -d postgres -x -c "SELECT status, sender_host, sender_port, slot_name, written_lsn, flushed_lsn, latest_end_lsn FROM pg_stat_wal_receiver;"

Expected: recovery is t, receiver status is streaming, sender matches the primary, and the slot matches this replica.

On the primary:

sudo -iu postgres psql -d postgres -x -c "SELECT application_name, client_addr, state, sync_state, sent_lsn, write_lsn, flush_lsn, replay_lsn FROM pg_stat_replication;"
sudo -iu postgres psql -d postgres -c "SELECT slot_name, active, pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn)) AS retained_wal FROM pg_replication_slots;"
Monitor replication slotsAn inactive slot can retain WAL until the primary disk fills. Alert on inactive slots, replication lag, and retained WAL size.

Completion checklist

  • pg_is_in_recovery() returns t on the standby.
  • pg_stat_wal_receiver.status is streaming.
  • The primary shows this standby in pg_stat_replication.
  • The dedicated slot is active and retained WAL is monitored.
  • A read-only application smoke test succeeds against the standby.
