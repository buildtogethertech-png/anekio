Restore a PostgreSQL backup

Restores a verified custom-format dump into a new database so the existing database remains untouched until validation and cutover approval.

Never restore over the only working copy This procedure creates a new target database. Do not use --clean, drop the current production database, or redirect application traffic until validation and approval are complete.

Preconditions

  • The dump, globals file, and checksum are copied to the restore host.
  • The current database and original backup remain untouched.
  • The restore target is PostgreSQL 15 and the dump was produced by compatible tooling.
  • Enough data, WAL, temporary, and index-build space is available.
  • For disaster cutover, application writes are stopped or directed away from the target.

Verify backup files are present and intact

sudo -u postgres test -s "{{RUNBOOK_DUMP}}"
sudo -u postgres test -s "{{RUNBOOK_GLOBALS}}"
sudo -u postgres test -s "{{RUNBOOK_CHECKSUM}}"
sudo -u postgres sha256sum --check "{{RUNBOOK_CHECKSUM}}"

Every file check must pass and every checksum line must return OK.

Verify target name is new

sudo -iu postgres psql -d postgres -c "SELECT datname FROM pg_database WHERE datname = '{{RUNBOOK_TARGET_DB}}';"

The query must return zero rows. If it returns a database, choose a different target name.

Verify PostgreSQL version and archive compatibility

/usr/lib/postgresql/15/bin/pg_restore --version
sudo -iu postgres psql -d postgres -c "SELECT version();"
sudo -iu postgres psql -d postgres -c "SHOW config_file; SHOW hba_file; SHOW data_directory;"
sudo -u postgres /usr/lib/postgresql/15/bin/pg_restore --list "{{RUNBOOK_DUMP}}" > /dev/null

The restore tools and target server should be PostgreSQL 15, and the archive list command must succeed.

Verify restore capacity and write freeze

RUNBOOK_DATA_DIR="$(sudo -iu postgres psql -d postgres -Atqc "SHOW data_directory;")"
printf 'Active data directory: %s\n' "$RUNBOOK_DATA_DIR"
df -h "$RUNBOOK_DATA_DIR" /tmp
sudo -iu postgres psql -d postgres -c "SELECT datname, pg_size_pretty(pg_database_size(datname)) FROM pg_database ORDER BY pg_database_size(datname) DESC;"

Tick capacity only after the restore host has enough room. Tick write-freeze only after the incident commander confirms application writes are stopped or routed elsewhere.

1. Fill restore inputs

Use the exact downloaded file paths. The generated commands must point to a new target database, not the current live one.

Fill these once, then copy the variables block and continue downward.

printf 'Dump: %s\nGlobals: %s\nChecksum: %s\nTarget: %s\nOwner: %s\nJobs: %s\n' \
  "{{RUNBOOK_DUMP}}" \
  "{{RUNBOOK_GLOBALS}}" \
  "{{RUNBOOK_CHECKSUM}}" \
  "{{RUNBOOK_TARGET_DB}}" \
  "{{RUNBOOK_OWNER}}" \
  "{{RUNBOOK_JOBS}}"
Stop conditionThe target name must not be the current production or staging database name.

2. Verify files and compatibility

sudo -u postgres sha256sum --check "$RUNBOOK_CHECKSUM"
sudo -u postgres /usr/lib/postgresql/15/bin/pg_restore --list "$RUNBOOK_DUMP" > /dev/null
/usr/lib/postgresql/15/bin/pg_restore --version
sudo -iu postgres psql -d postgres -c "SELECT version();"
sudo -iu postgres psql -d postgres -c "SHOW config_file; SHOW hba_file; SHOW data_directory;"
RUNBOOK_DATA_DIR="$(sudo -iu postgres psql -d postgres -Atqc "SHOW data_directory;")"
df -h "$RUNBOOK_DATA_DIR"

All checksums must report OK. A downgrade from a newer PostgreSQL server is not guaranteed; test it before an incident instead of relying on a newer client to make it safe.

3. Review roles before applying them

The globals file can create or alter cluster-wide roles and contains sensitive password hashes. Never apply it blindly to an existing shared cluster.

sudo -u postgres grep -E '^(CREATE|ALTER) ROLE' "$RUNBOOK_GLOBALS"

On a brand-new isolated recovery cluster, apply the reviewed globals file:

sudo -u postgres /usr/lib/postgresql/15/bin/psql \
  --dbname=postgres \
  --set=ON_ERROR_STOP=1 \
  --file="$RUNBOOK_GLOBALS"

On an existing cluster, create only the required owner if it is missing:

sudo -iu postgres psql -d postgres -c "\du $RUNBOOK_OWNER"
sudo -iu postgres psql -d postgres

Inside psql, create the role only if the previous check showed it was absent:

CREATE ROLE {{RUNBOOK_OWNER}} LOGIN;
\password {{RUNBOOK_OWNER}}
\q

4. Create a clean target database

sudo -iu postgres createdb \
  --template=template0 \
  --owner="$RUNBOOK_OWNER" \
  "$RUNBOOK_TARGET_DB"

sudo -iu postgres psql -d postgres -c "SELECT datname FROM pg_database WHERE datname = '$RUNBOOK_TARGET_DB';"

5. Restore the archive

Parallel restore is supported by custom-format archives. Set jobs according to measured CPU, disk, and connection capacity.

sudo -iu postgres /usr/lib/postgresql/15/bin/pg_restore \
  --dbname="$RUNBOOK_TARGET_DB" \
  --no-owner \
  --role="$RUNBOOK_OWNER" \
  --exit-on-error \
  --jobs="$RUNBOOK_JOBS" \
  --verbose \
  "$RUNBOOK_DUMP"
PG_RESTORE_EXIT=$?
printf 'pg_restore exit code: %s\n' "$PG_RESTORE_EXIT"
test "$PG_RESTORE_EXIT" -eq 0
If restore failsSave the complete error output. Because parallel restore is not a single transaction, the new target may be partial. Do not rerun into it; remove only this newly created target after confirming its name, then correct the error and start again.

6. Validate the restored database

sudo -iu postgres psql -d "$RUNBOOK_TARGET_DB" -c "SELECT current_database(), pg_size_pretty(pg_database_size(current_database()));"
sudo -iu postgres psql -d "$RUNBOOK_TARGET_DB" -c "SELECT extname, extversion FROM pg_extension ORDER BY 1;"
sudo -iu postgres psql -d "$RUNBOOK_TARGET_DB" -c "SELECT schemaname, count(*) AS tables FROM pg_tables WHERE schemaname NOT IN ('pg_catalog','information_schema') GROUP BY 1 ORDER BY 1;"
sudo -iu postgres psql -d "$RUNBOOK_TARGET_DB" -c "SELECT count(*) AS invalid_indexes FROM pg_index WHERE NOT indisvalid;"
sudo -iu postgres vacuumdb --analyze-in-stages --dbname="$RUNBOOK_TARGET_DB"

Compare critical row counts and business totals with the backup manifest or source. Then point a non-production application instance at the restored database and complete application smoke tests.

7. Remove a failed test target only

Destructive commandRun this only when the printed name is the newly created failed/test database and incident leadership has confirmed it is safe. Never substitute the live database.
printf 'Database selected for removal: %s\n' "$RUNBOOK_TARGET_DB"
sudo -iu postgres psql -d postgres -c "SELECT datname, pg_size_pretty(pg_database_size(datname)) FROM pg_database WHERE datname = '$RUNBOOK_TARGET_DB';"
sudo -iu postgres dropdb "$RUNBOOK_TARGET_DB"

Cutover requires a separate decision

Do not rename databases or change application connection strings as part of this restore procedure. Obtain approval after data validation, record a rollback endpoint, stop writes, switch the application, and monitor errors and business checks.
