Take a backup of the current database

Creates a portable custom-format dump, captures cluster roles separately, validates the archive, and moves the result off the database host.

Expected impact pg_dump takes a transactionally consistent backup while the database remains available. It does not block normal readers and writers, but it consumes CPU, disk I/O, and storage bandwidth.

Preconditions

  • The exact source database and server have been confirmed.
  • The PostgreSQL 15 client tools are installed.
  • The backup directory has enough free space and is not on the PostgreSQL data volume.
  • An approved encrypted off-host destination is ready.

Verify source database and server

hostname -f
sudo -iu postgres psql -d postgres -c "SELECT version(), pg_is_in_recovery();"
sudo -iu postgres psql -d postgres -c "SHOW config_file; SHOW hba_file; SHOW data_directory;"
sudo -iu postgres psql -d postgres -c "SELECT datname, pg_size_pretty(pg_database_size(datname)) FROM pg_database ORDER BY pg_database_size(datname) DESC;"

Tick the box only after the hostname is the intended source and pg_is_in_recovery() is expected for this backup plan.

Verify PostgreSQL 15 tools

/usr/lib/postgresql/15/bin/pg_dump --version
/usr/lib/postgresql/15/bin/pg_restore --version
/usr/lib/postgresql/15/bin/pg_dumpall --version

All commands should report PostgreSQL 15.x.

Verify backup disk and ownership

RUNBOOK_DATA_DIR="$(sudo -iu postgres psql -d postgres -Atqc "SHOW data_directory;")"
printf 'Active data directory: %s\n' "$RUNBOOK_DATA_DIR"
sudo install -d -o postgres -g postgres -m 700 "{{RUNBOOK_BACKUP_DIR}}"
df -h "{{RUNBOOK_BACKUP_DIR}}" "$RUNBOOK_DATA_DIR"
sudo -u postgres test -w "{{RUNBOOK_BACKUP_DIR}}" && echo "Backup directory is writable"

The backup path must have enough free space and should not be the same full data volume you are protecting.

Verify off-host storage access

sudo -u postgres aws s3 ls "{{RUNBOOK_S3_BASE}}/"

Tick this only when the approved encrypted destination is reachable by the account that will upload the backup.

1. Confirm the source

The recovery check must return f. If it returns t, you are on a standby; stop and confirm whether backing up the standby is intentional.

hostname -f
sudo -iu postgres psql -d postgres -c "SELECT version(), pg_is_in_recovery();"
sudo -iu postgres psql -d postgres -c "SHOW config_file; SHOW hba_file; SHOW data_directory;"
sudo -iu postgres psql -d postgres -c "SELECT datname, pg_size_pretty(pg_database_size(datname)) FROM pg_database ORDER BY pg_database_size(datname) DESC;"

2. Fill backup inputs

Enter the values once. The commands on this page update immediately, so the operator can copy each block without editing placeholders by hand.

Keep the generated UTC timestamp unchanged for the entire run after copying the variables block.

printf 'Database: %s\nBackup directory: %s\nDump: %s\nGlobals: %s\nChecksum: %s\n' \
  "{{RUNBOOK_DB}}" \
  "{{RUNBOOK_BACKUP_DIR}}" \
  "{{RUNBOOK_DUMP}}" \
  "{{RUNBOOK_GLOBALS}}" \
  "{{RUNBOOK_CHECKSUM}}"
Stop conditionDo not continue if the printed database or paths are wrong.

3. Prepare protected storage

sudo install -d -o postgres -g postgres -m 700 "$RUNBOOK_BACKUP_DIR"
df -h "$RUNBOOK_BACKUP_DIR"
sudo -u postgres test -w "$RUNBOOK_BACKUP_DIR" && echo "Backup directory is writable"

Available space should comfortably exceed the expected compressed dump size. If it does not, stop and attach or select suitable storage.

4. Create the database dump

sudo -u postgres /usr/lib/postgresql/15/bin/pg_dump \
  --format=custom \
  --compress=6 \
  --verbose \
  --dbname="$RUNBOOK_DB" \
  --file="$RUNBOOK_DUMP"
PG_DUMP_EXIT=$?
printf 'pg_dump exit code: %s\n' "$PG_DUMP_EXIT"
test "$PG_DUMP_EXIT" -eq 0

Continue only when the exit code is 0.

5. Back up cluster roles

Database dumps do not include cluster-wide roles. The globals file may contain password hashes; handle it as a secret.

sudo -u postgres /usr/lib/postgresql/15/bin/pg_dumpall \
  --globals-only \
  --file="$RUNBOOK_GLOBALS"

sudo chmod 600 "$RUNBOOK_GLOBALS"
sudo chown postgres:postgres "$RUNBOOK_GLOBALS"

6. Validate the backup

sudo -u postgres /usr/lib/postgresql/15/bin/pg_restore --list "$RUNBOOK_DUMP" > /dev/null
sudo -u postgres test -s "$RUNBOOK_DUMP"
sudo -u postgres test -s "$RUNBOOK_GLOBALS"
sudo -u postgres sha256sum "$RUNBOOK_DUMP" "$RUNBOOK_GLOBALS" | sudo tee "$RUNBOOK_CHECKSUM" > /dev/null
sudo chmod 600 "$RUNBOOK_CHECKSUM"
sudo chown postgres:postgres "$RUNBOOK_CHECKSUM"
sudo ls -lh "$RUNBOOK_DUMP" "$RUNBOOK_GLOBALS" "$RUNBOOK_CHECKSUM"
A list check is not a restore testThe backup is not proven until it has been restored into an isolated database and application smoke checks pass.

7. Copy the backup off the host

Use the approved encrypted backup destination. Example for an approved S3 bucket:

sudo -u postgres aws s3 cp "{{RUNBOOK_DUMP}}" "{{RUNBOOK_S3_PREFIX}}"
sudo -u postgres aws s3 cp "{{RUNBOOK_GLOBALS}}" "{{RUNBOOK_S3_PREFIX}}"
sudo -u postgres aws s3 cp "{{RUNBOOK_CHECKSUM}}" "{{RUNBOOK_S3_PREFIX}}"
sudo -u postgres aws s3 ls "{{RUNBOOK_S3_PREFIX}}"

If AWS CLI access is not configured for the postgres user, use the organization-approved transfer mechanism. Do not weaken file permissions or place secrets in a public bucket.

Completion checklist

  • pg_dump exited with code 0.
  • pg_restore --list succeeded.
  • Dump, globals, and checksum files are stored together.
  • An encrypted off-host copy was listed and verified.
  • A restore test is scheduled or completed.
